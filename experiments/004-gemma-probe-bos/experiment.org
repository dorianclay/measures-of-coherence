* DRAFT 004 Gemma IT probes: is the failure a missing BOS token? :exploratory:

** Question
Did linear probes fail on =gemma-4-12B-it= in 001 because its statements reached the model without a BOS token, rather than because of the model? =probing.activations= tokenized raw statements with the tokenizer's defaults: =gemma-4-12B='s adds =<bos>=, =gemma-4-12B-it='s doesn't. Elicited prompts had =<bos>= from the chat template, and elicitation worked. Exploratory: this decides what to test next, and changes nothing in 001.

** Hypothesis
Exploratory, so nothing is registered. Expected if BOS is the cause: with =<bos>= added, =gemma-4-12B-it= reaches about the base model's probe accuracy in 001 (validation 0.74–0.87, booked 0.68–0.70), against its 0.56 and 0.52 there; with =<bos>= removed, =gemma-4-12B= falls to about those failing numbers.

** Analysis plan
- *Runs*, through =slurm/probe_bos.sbatch=, one job per arm:
  - =gemma-4-12B-it=, =--bos add=;
  - =gemma-4-12B=, =--bos remove=.
  Each job runs activations on all of 001's datasets, then 001's domain-swap and atomic-only probes (=probing.family_probes=, its defaults) and rates of loss. 001's own results are the other two arms. These runs log no protocol: they are not =belief-probe-linear@1=, whose extraction is what's in question.
- *Check that 001 is what we think it was.* Each job also extracts =facts= with the tokenizer's defaults. Those should match 001's saved activations (in =~/code/Probes/activations/=), and the forced arm should differ from them for the model it changes.
- *Read off.* From =analysis/bos_effect.py=: per model, arm and booked domain, the headline layer as in 001 (domain-swap linear, best validation accuracy), its validation and booked accuracy, and its mean L on negation pairs and conjunctions, beside 001's numbers.
- *Then.* If both arms move as expected, BOS is the cause: ask the author about a new probe protocol and about 001's Findings. If =gemma-4-12B-it= stays near chance with =<bos>=, try statements in a chat turn. If it improves only partly, do both.

*** DONE Second question: how the statement is presented
The BOS arms left =gemma-4-12B-it= near chance (=figures/bos_effect.csv=), so, per the plan above, this is next. The author set the aim on 2026-11-05: a probing method robust enough to test a wider spread of open models, so the choice of models for the rest of the thesis can be made with confidence. The order: BOS, then presentation, and only then tuning the probe.

- *Presentations* (=--presentation= in =probing.activations=), all without a system prompt of ours, all with 001's probes and datasets:
  - =chat-statement=: the statement in a user turn, read at its last token;
  - =chat-turn=: the same prompt, read at the last token before the model's reply;
  - =judge-turn=: the user turn asks whether the statement is true (001's elicitation template t0), read at the same place.
- *Models.* The instruct models of 001: =gemma-4-12B-it= and Qwen2.5 1.5B, 7B and 14B Instruct. Base models have no user turn to present in. Baseline: raw text with BOS, i.e. 001 for Qwen and for base Gemma, 004's =bos=add= for =gemma-4-12B-it=.
- *What robust means*, written before these results. One recipe (presentation, probe, layer rule), the same for every model, with no per-model adjustment, whose headline probe reaches booked accuracy of at least 0.65 (001's competence bar for elicitation) in both booking directions on every instruct model, chosen by validation accuracy only. A model that misses it is reported with the recipe, not worked around.
- *Selection.* Comparing presentations on these four models and then picking one can overstate how well it works. The wider set of models is the test of the chosen recipe; these are not.
- *Read off.* =analysis/presentation_effect.py=: per model, presentation and booked domain, headline layer, validation and booked accuracy, linear and MLP, mean L raw and calibrated.
