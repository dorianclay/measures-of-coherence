#+TITLE: Design: how experiments and runs are recorded
#+DATE: 2026-11-03

Settled in a grilling session with the author on 2026-11-03. It drives the top-level =CLAUDE.md= and the pipeline code. The aim is that every number in the thesis traces back to the code, config, model, data and command that produced it, and to the decisions behind it.

The thesis plan this serves (from the author's meeting notes, "Thesis project overview"): RL a model on a minimal decision game (umbrella/rain, varying /p/), measuring the coherence of its beliefs and values by probing and elicitation at checkpoints during training; then games with an opponent; then decision-theory variants. The end-of-November 2026 deadline covers the full umbrella/rain experiment.

* Structure
- Two levels. An *experiment* is one research question with a hypothesis, analysis plan, decision log and findings. A *run* is one execution: one config, one model reference, one seed. A run belongs to exactly one experiment.
- Experiments get sequential ids (=002-umbrella-rl-belief-coherence=). Runs get time-sortable, collision-free ids (=20261103-1412-a3f9=), so cluster jobs never clash.
- Two run kinds, training and measurement, in one system. They join through a *model reference*: a base model (HF id + revision) or =<training-run-id>@step<N>=.
- *Activation extraction* is its own run, producing an artifact keyed by (model reference, layers, dataset version, extraction protocol). Probe runs cite it as input, so all probe methods (linear, MLP, mass-mean, …) train on the same activations.

* Files and layout
- Org for anything people write or read: =experiment.org=, the generated =experiments/index.org=, =ROADMAP.org=. JSON for anything code writes: =run.json= per run, plus its =config.yaml=. A script keeps a run table (id, status, model reference, note) inside each =experiment.org=.
- Git is the source of truth. A hosted tracker (e.g. W&B) is optional, for live training curves only, linked from =run.json= by URL.

- One uv project at the root: one =pyproject.toml=, =uv.lock=, =.venv=. Torch-only; the upstream TensorFlow scripts are deleted (history keeps them).
- Large artifacts live at =$COHERENCE_STORE/<run-id>/= on the cluster. Each run's record lists a manifest of them (path, size, sha256). Checkpoints that a cited result depends on are also pushed to a private Hugging Face repo.

* Provenance
- =record= wraps any command: =uv run record --experiment 002 --note "…" -- <command>=. It creates the run directory, exports =RUN_ID= and =RUN_DIR=, captures stdout/stderr, and writes the /how/: git SHA, diff of uncommitted changes, full command, working directory, =uv.lock= hash, SLURM job id, host, GPU, start/end, exit code, status.
- Our own scripts add the /what/ through a library call, =coherence.runs.log(model_ref=…, protocol=…, datasets=[…], artifacts=[…])=, which is a no-op outside =record=. In a pre-registered experiment, a run that doesn't log a model reference and protocol fails.
- Datasets carry a version and sha256 in a dataset manifest; every run records the versions it read. Fixing data makes a new version, never a silent edit.
- Every measurement has a named, versioned *protocol* (=belief-elicit-logprob@1=, =belief-probe-linear@1=) fixing templates, aggregation and dataset version. Analysis refuses to put different protocol versions in one table or plot unless that is the point of the comparison.
- Every figure and table comes from a script that takes run ids, and gets a sidecar listing run ids, protocol versions and the analysis commit. Findings cite figures by path. No hand-edited figures or tables.

* Training on the cluster
The cluster caps a job at 48 GPU-hours.
- A training run that spans jobs stays one run. Each slurm job is a *segment* appended to =run.json= (job id, host, SHA, start/end, step range, exit status), started with =record --resume <run-id> -- <command>=.
- A segment refuses to start if the git SHA or =uv.lock= differs from the first segment's, unless =--allow-drift "<reason>"= is given; that is logged, and counts as a deviation on registered experiments.
- A run stays =running= until a segment completes the planned steps. A failed segment leaves the run resumable, not failed.
- Two checkpoint kinds in the manifest. *Eval checkpoints*: weights only, on the plan's measurement schedule, permanent, valid model references. *Resume state*: weights, optimizer, RNG and data position, overwritten, only the latest kept, never a model reference.
- =submit-chain <run-id> --segments K= submits K jobs linked by =--dependency=afterok=. The training loop saves resume state on a wall-clock deadline well before 48 h. A failed segment stops the chain and is recorded.
- Measurement during training is separate measurement runs on saved eval checkpoints, never code in the training loop. One measurement path serves base models and checkpoints, and new measures can be applied to old checkpoints.

* Honesty rules
- Pre-registration: before an experiment's first real run, its hypothesis and analysis plan are committed (state =REGISTERED=). Later changes are dated deviation entries, never edits. Experiments marked =exploratory= skip this.
- A registered experiment refuses runs from a dirty tree. Exploratory experiments allow it and save the diff in the run directory.
- Every run keeps its record forever, with status =running= / =succeeded= / =failed= / =abandoned= and a one-line reason. Large artifacts may be deleted; records may not.
- Every stochastic run takes an explicit =--seed=. A registered plan states seeds per condition up front. Analysis covers every seed that ran.
- Experiment lifecycle as Org TODO keywords: =#+TODO: DRAFT REGISTERED RUNNING | CONCLUDED ABANDONED=. =experiments/index.org= is generated from them.

* Tasks and roadmap
- Wayfinder maps and tickets are replaced by Org: each experiment's tasks are TODO headings under =* Tasks= in its =experiment.org=.
- =ROADMAP.org= holds the thesis arc and links stages to experiments. The author's meeting notes in =~/org= stay the author's; when they disagree, the roadmap is updated.

* Branches and commits
- =setup= merges to =main= once the restructure lands with tests passing.
- Then each experiment gets =exp/NNN-slug= for code changes. Run-record commits go to the branch the code ran from, so every run's SHA stays reachable. An experiment's branch merges to =main= when its code is stable, by =CONCLUDED= or =ABANDONED= at the latest.
- One commit per finished unit of work.

* Implementation notes
Choices made while building step 3 that the session above didn't spell out:
- A DRAFT experiment, like an exploratory one, may run uncommitted code (with =diff.patch= saved). Only REGISTERED and later states that aren't exploratory require a clean tree.
- The uncommitted-code check ignores what runs and analysis generate: =experiments/*/runs/**=, =experiments/*/figures/**=, each =experiment.org= (its run table) and =experiments/index.org=.
- Artifact paths in the manifest are relative to =$COHERENCE_STORE=, so records survive the store moving between machines. Artifacts outside the store are refused.
- =run.json= holds per-job fields in =segments= from the start, so step 4 adds segments without a schema change.
- Sidecars are =<output>.sources.json= next to each figure or table.
- Experiment 001's pipeline scripts don't call =coherence.runs.log= yet. One invocation of =probing.family_probes= or =coherence.elicitation= produces several protocols at once, which doesn't fit one run, one protocol. Experiment 002's measurement code should be written to log one protocol per run.

Choices made while building step 4:
- A run is a training run when it logs =planned_steps=; only training runs resume. =coherence.runs.progress(step)= records the last completed step, =runs.step()= reads it back, and each segment records its step range. A segment exits 0 when it stops early on purpose, so the chain goes on; the run is =succeeded= only once a segment reaches the planned steps.
- =record --resume <run-id>= reruns the run's own command; a different command isn't allowed. Resuming a completed run does nothing and exits 0, so spare jobs at the end of a chain are harmless. A segment whose job died without record writing its end (SIGKILL, node failure) is marked =interrupted= by the next resume. =record= passes slurm's SIGTERM on to the command and outlives it, so a job stopped at its time limit still records its segment.
- Drift compares the commit, =uv.lock= and, for DRAFT experiments, the uncommitted diff (=diff.patch= for the first segment, =diff.segment<N>.patch= after) against the first segment. =uv_lock_sha256= is per segment. Allowed drift is stored on the segment with its reason; on a registered experiment it is flagged =deviation: true= and =record= says a deviation entry is needed, which still needs the author's sign-off.
- Checkpoints are manifest entries with =checkpoint: eval|resume= and =step=, logged with =runs.checkpoint(path, step=…, kind=…)=; a checkpoint may be a directory (hashed over its files). Resume state is not hashed and the manifest keeps only the latest; =runs.resume_state()= returns its path and step. =runs.model_path("<run-id>@step<N>")= finds an eval checkpoint, and =runs.log= refuses a checkpoint reference with no eval checkpoint at that step.
- =runs.out_of_time(margin_seconds)= is the training loop's wall-clock check: it reads =SLURM_JOB_END_TIME=, falling back to =squeue=. Whether the cluster's slurm sets that variable is unchecked; the fallback covers either case.
- =submit-chain= picks the new run's id itself and passes it to =record --run-id=, so all K jobs can be submitted before the first starts. Jobs after the first use =--dependency=afterok= with =--kill-on-invalid-dep=yes=, so a failed segment cancels the rest instead of leaving them pending. When extending a run whose last segment is still going, the first new job waits for that segment's job. Every job runs =slurm/record.sbatch=.
